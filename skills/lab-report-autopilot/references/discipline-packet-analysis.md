# Packet capture and protocol analysis

## Environment route

- Use Windows Wireshark with PowerShell or Command Prompt when the assignment follows the usual Windows classroom workflow.
- Use Linux or Kali for Linux interfaces, command-line tools, or an isolated multi-host topology.
- Use macOS Wireshark or `tshark` only when the assignment accepts the host network and the required evidence is equivalent.
- Record the interface, relevant addresses, Wireshark/tshark version, and capture time in working notes. Put only values used by the report into the final text.

Capture only traffic generated by the user, a local lab, or an authorized course network.

## Capture rules

1. State the interface and why it carries the target traffic.
2. Distinguish a capture filter from a display filter:
   - Capture filter example: `icmp or arp`
   - Display filter example: `arp.opcode == 2`
3. Generate finite, repeatable traffic:

   ```bash
   ping -c 4 <LAB_IP>
   dig example.com
   curl --max-time 10 http://<LAB_IP>/
   ```

4. Preserve the original `.pcap` or `.pcapng`.
5. Record the exact filter, frame number, timestamp, source, destination, protocol, and length for every analyzed packet.
6. Select the packet before taking the screenshot. Keep the packet list and decoded field tree readable.
7. Expand only the layers discussed in the text.

For a bounded CLI capture:

```bash
tshark -D
tshark -i <INTERFACE> -a duration:30 -f "icmp or arp" -w capture.pcapng
tshark -r capture.pcapng -Y "arp or icmp"
```

## Analysis by protocol

- **Ethernet:** source and destination MAC, EtherType.
- **ARP:** opcode, sender/target IP and MAC, request-response relationship.
- **IPv4/IPv6:** source, destination, TTL/hop limit, protocol/next header.
- **ICMP:** type, code, identifier, sequence, request-response pairing.
- **TCP:** source/destination port, flags, sequence, acknowledgment, handshake order.
- **DNS:** transaction ID, query name/type, response code, answer records, timing.
- **HTTP:** method, host, path, status, headers; redact tokens and private parameters.

## Evidence selection

- A simple request-response experiment normally uses three figures: the full flow, the selected request fields, and the selected response fields.
- Combine setup and traffic generation into text when the commands are short and the result is visible in Wireshark.
- When a display filter leaves one or two packet rows, move the horizontal divider upward and give the decoded-field pane most of the window height.
- Keep enough application context to show Wireshark, the active display filter, frame number, and discussed fields.
- Preserve the capture file even when it is not shown as a separate figure.

## Report analysis

Tie prose to frame numbers:

> 第 18 帧是 ARP 请求，`Target MAC address` 尚未确定；第 19 帧返回对应 MAC 地址。两帧的发送方与目标字段互换，说明地址解析已经完成。

Do not call `tcp.port == 80` a capture filter, analyze an unselected packet, hide the frame number, or infer fields that are not visible.
