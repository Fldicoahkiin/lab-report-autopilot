# Programming and data structures

## Environment route

- Use the required compiler or runtime.
- Record language version, build command, source filename, inputs, and execution command.
- Prefer native Windows when the assignment names Visual Studio, Dev-C++, a Windows API, or a specific Windows console. Cross-platform compilers may run on the current host.

## Implementation rules

- Implement only the requested behavior.
- Use the data structure or algorithm named by the assignment.
- Keep input data small and deterministic unless randomization is part of the task.
- Avoid unused classes, generic frameworks, configuration layers, broad exception handling, and explanatory comments on obvious lines.
- Run the exact source shown in the report.

## Minimum evidence

- Readable source or the relevant function.
- Build command and successful compiler output when compilation is required.
- Program input and output.
- Multiple test cases when boundary behavior is part of the task.
- Intermediate state only when it explains the algorithm.

## Result analysis

For algorithms, cover the requested properties:

- input and output;
- main state transition;
- time and space complexity;
- stability or ordering property;
- why the test demonstrates correctness.

Do not claim correctness from compilation alone. Do not include code that was not executed.
