# Web development

## Environment route

- Use the repository's package manager and local browser.
- Record browser version, viewport, local URL, build/dev command, and main source files.
- Use a Windows guest only when the assignment requires a Windows-only editor or browser behavior.

## Execution sequence

1. Start the site with a bounded local command or the project's dev server.
2. Verify the page loads without console errors.
3. Test the required interaction.
4. Test the named viewport sizes.
5. Inspect network requests when data loading is part of the task.
6. Capture the final rendered state and relevant developer-tool evidence.

## Minimum evidence

- Relevant HTML/CSS/JavaScript or component source.
- Browser-rendered page.
- Interaction before/after when required.
- Console and network state when they support a claim.
- Responsive view at required widths.

## Result analysis

Explain the visible behavior and the source rule that causes it. For layout work, name the container, breakpoint, grid/flex rule, or selector.

Do not submit source code without a rendered page, hide console errors, or use a screenshot that crops out the interaction result.
